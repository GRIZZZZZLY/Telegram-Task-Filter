# Plan S4: AI-классификация + Fuzzy-дедупликация + Local LLM

## Статус: ⏳ ЗАПЛАНИРОВАНА (не начата)

---

## Цель

Добавить интеллектуальный слой поверх существующего rule-engine:
1. **AI-классификация** — автоматически определять приоритет и категорию задачи по смыслу текста
2. **Fuzzy-дедупликация** — не создавать задачи для семантически похожих сообщений
3. **Local LLM** — работать без интернета и без платных API через llama.cpp / ollama

Rule-engine остаётся основным фильтром (кто создаёт задачи). AI — второй слой (как классифицировать и дедуплицировать).

---

## Архитектурный принцип

```
Telegram message
      ↓
  rule_engine.evaluate()          ← существующий, не меняется
      ↓ create_task=True
  dedup_service.is_duplicate()    ← НОВЫЙ: fuzzy similarity check
      ↓ not duplicate
  task = Task(priority=rule_priority)
      ↓ если AI_ENABLED=true
  ai_service.classify(text)       ← НОВЫЙ: async, timeout 5s
      ↓ если ответ получен
  task.priority = max(rule_priority, ai_priority)
  task.ai_category = ai_category
      ↓
  db.persist(task)
  ws.broadcast(task)
```

**Ключевые гарантии:**
- AI никогда не блокирует создание задачи (timeout → fallback на rule priority)
- Fuzzy dedup не трогает точные дубли (уже есть проверка по `source_message_id`)
- `AI_ENABLED=false` → поведение идентично текущему

## Часть 1 — Fuzzy-дедупликация

### 1.1 `dedup_service.py`

**Файл:** `services/api/app/services/dedup_service.py`

```python
from difflib import SequenceMatcher  # stdlib, без зависимостей

def is_duplicate(title: str, db: Session, window_minutes: int = 60) -> bool:
    """
    Возвращает True если в БД есть задача с похожим title,
    созданная в последние window_minutes минут.
    """
```

**Алгоритм:**
1. Выбрать задачи из БД за последние `window_minutes` минут
2. Для каждой: `ratio = SequenceMatcher(None, title.lower(), existing.title.lower()).ratio()`
3. Если `ratio >= DEDUP_SIMILARITY_THRESHOLD` → дубль
4. Лог: `"Skipped as duplicate (similarity=0.91): 'Позвонить Игорю сегодня' ~ 'Позвонить Игорю'"`

**Примеры порога 0.88:**

| Пара | Ratio | Результат |
|------|-------|-----------|
| «Позвонить Игорю» / «Позвонить Игорю!» | ~0.94 | ❌ дубль |
| «Позвонить Игорю» / «Позвонить Игорю сегодня» | ~0.80 | ✅ разные |
| «Сделать отчёт» / «Сделать отчёт срочно» | ~0.82 | ✅ разные |
| «Fix bug» / «Fix bug» | 1.00 | ❌ дубль |

**Настройка:** `DEDUP_SIMILARITY_THRESHOLD=0.88` в `.env` (добавить в `Settings` и `config.py`)

**Зависимости:** только stdlib `difflib` — ничего устанавливать не нужно.

### 1.2 Интеграция в `tg_listener.py`

```python
# После rule_engine, перед persist:
from ..services.dedup_service import is_duplicate

title = _extract_title(text)
if is_duplicate(title, db):
    logger.info("MSG skipped — fuzzy duplicate: %.60r", title)

```

Аналогично в `catchup_worker.py`.

### 1.3 Тесты `test_dedup_service.py`

- Точный дубль → True
- Похожий выше порога → True

- Пустая БД → False

## Часть 2 — AI-классификация (Cloud API)

### 2.1 `ai_service.py`

**Файл:** `services/api/app/services/ai_service.py`

```python
from dataclasses import dataclass

@dataclass
class AiResult:
    priority: str        # "high" | "medium" | "low" | "normal"
    category: str        # "Работа" | "Личное" | "Финансы" | ...
    reasoning: str       # краткое объяснение (для логов)

async def classify(text: str) -> AiResult | None:
    """
    Классифицирует текст через настроенный провайдер.
    Возвращает None при ошибке / таймауте / AI_ENABLED=false.
    """
```

**Промпт (системный, на русском):**
```
Ты — ассистент для классификации задач из Telegram-сообщений.
Определи приоритет и категорию задачи.

Приоритеты:
- high: срочно, горит, дедлайн сегодня, критично
- medium: важно, нужно сделать, не забудь
- low: когда будет время, не срочно, можно потом
- normal: всё остальное

Категории (выбери одну): Работа, Личное, Финансы, Здоровье, Обучение, Покупки, Другое

Верни ТОЛЬКО JSON: {"priority": "...", "category": "...", "reasoning": "..."}
```

**Провайдеры:**

| Провайдер | Модель по умолчанию | Стоимость |
|-----------|---------------------|-----------|
| OpenAI | `gpt-4o-mini` | ~$0.00015 / 1K tokens |
| Anthropic | `claude-haiku-3-5` | ~$0.00025 / 1K tokens |
| Local (ollama) | `llama3.2:3b` | бесплатно |
| Local (llama.cpp) | `llama-3.2-3b-q4` | бесплатно |

**Реализация через `httpx`** (один пакет, без тяжёлых SDK):
```python
import httpx

async with httpx.AsyncClient(timeout=5.0) as client:
    response = await client.post(endpoint, headers=headers, json=payload)
```

**Безопасность API-ключа:**
- Хранится в DPAPI (механизм уже готов из S2/S3)
- Новый endpoint `POST /auth/ai-key` → сохраняет в DPAPI под ключом `AI_API_KEY`
- GET-запросы никогда не возвращают ключ — только статус `{"key_set": true/false}`

## Часть 3 — Local LLM (ollama / llama.cpp)

### Зачем

- Работа без интернета
- Нет платы за токены
- Данные не покидают машину (приватность)
- Подходит для чувствительных рабочих чатов

### 3.1 Провайдер `ollama`

Ollama поднимает OpenAI-совместимый API на `http://localhost:11434`. Реализация — тот же `httpx`, только другой endpoint:

```python
# Ollama совместим с OpenAI API format
endpoint = "http://localhost:11434/v1/chat/completions"
# API-ключ не нужен (или любая строка)
```

**Настройка в `.env`:**
```
AI_PROVIDER=ollama
AI_MODEL=llama3.2:3b
AI_OLLAMA_URL=http://localhost:11434  # можно переопределить
```

**Установка пользователем** (один раз, вне приложения):
```powershell
winget install Ollama.Ollama
ollama pull llama3.2:3b
```

Приложение проверяет доступность ollama при старте и показывает статус в Settings.

### 3.2 Провайдер `llama.cpp` (HTTP server mode)

llama.cpp в режиме сервера (`llama-server`) тоже поднимает OpenAI-совместимый API:

```python
endpoint = f"{AI_LLAMACPP_URL}/v1/chat/completions"
# По умолчанию: http://localhost:8080
```

**Настройка в `.env`:**
```
AI_PROVIDER=llamacpp
AI_MODEL=llama-3.2-3b-q4_k_m  # имя модели для логов
AI_LLAMACPP_URL=http://localhost:8080
```

**Установка пользователем** (один раз):
```powershell
# Скачать llama-server.exe + модель .gguf
llama-server.exe -m llama-3.2-3b-q4_k_m.gguf --port 8080
```

### 3.3 Единый интерфейс провайдеров

```python
# ai_service.py — диспетчер
PROVIDERS = {
    "openai":    OpenAIProvider,
    "anthropic": AnthropicProvider,
    "ollama":    OllamaProvider,    # OpenAI-compatible
    "llamacpp":  LlamaCppProvider,  # OpenAI-compatible
}

async def classify(text: str) -> AiResult | None:
    provider = PROVIDERS.get(settings.ai_provider)
    if not provider:
        return None
    return await provider().classify(text)
```

`OllamaProvider` и `LlamaCppProvider` наследуют от `OpenAICompatibleProvider` — только разные URL и заголовки.

### 3.4 Health check для local LLM

Новый endpoint `GET /ai/status`:
```json
{
  "enabled": true,
  "provider": "ollama",
  "model": "llama3.2:3b",
  "reachable": true,       // пинг к ollama/llamacpp
  "key_set": null          // null для local (ключ не нужен)
}
```

В Settings показывается статус: `● Ollama доступен` / `○ Ollama недоступен`.

> **Статус: Parking Lot** — реализуется после основной части S4, если останется время/желание.

## Часть 6 — Fine-tuning и RAG (Отдельная тема)

> **Статус: Отдельная тема** — не входит в S4, требует отдельного планирования.

### Fine-tuning

Дообучение модели на реальных данных из проекта:
- Собрать датасет: `{text, priority, category}` из уже созданных задач
- Fine-tune через OpenAI API или локально через `llama.cpp` / `unsloth`
- Результат: модель, которая знает специфику конкретных чатов и терминологию

**Когда имеет смысл:** после накопления 500+ задач с ручными корректировками приоритета.

### RAG (Retrieval-Augmented Generation)

Контекстная классификация с учётом истории:
- Векторная БД (ChromaDB / sqlite-vec) хранит embeddings прошлых задач
- При новом сообщении — найти похожие задачи из истории
- Передать их в промпт как примеры: «Похожие задачи имели приоритет high»

**Когда имеет смысл:** когда базовая AI-классификация уже работает и нужна точность выше.

**Зависимости:** `sentence-transformers` или OpenAI embeddings API, ChromaDB или sqlite-vec.

## Acceptance Criteria

- Given `AI_ENABLED=true` + ключ OpenAI, when приходит «срочно сделать отчёт к утру», then задача создана с `priority=high`, `ai_category="Работа"`
- Given `AI_ENABLED=true` + ollama запущен, when приходит сообщение, then классификация работает без интернета
- Given две задачи «Позвонить Игорю» и «Позвонить Игорю!» в течение часа, when similarity=0.94 > 0.88, then вторая не создаётся + лог «skipped as duplicate»
- Given `AI_ENABLED=false`, when приходит сообщение, then поведение идентично текущему (rule-engine only)
- Given AI-провайдер недоступен / таймаут, when приходит сообщение, then задача создаётся с приоритетом от rule-engine + warning в логе
